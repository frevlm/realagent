# ADR-0034：TUI 换 Bubble Tea v2；对话按条目存；画面按区域排

- 状态：已采纳（2026-11-03）
- 依赖：ADR-0007（Go + Bubble Tea）、ADR-0020（altscreen，历史从会话记录渲染）

## 背景

在伪终端里用 pyte 驱动 TUI，问题都能复现：
- Bubble Tea v1 每帧把硬件光标停在左下角，输入法候选框跟着跑；帧也不是一次画完的。
- 底下那块没有高度上限：粘贴 40 行就把输入框顶出屏幕，开一个菜单历史区就整体重排。
- 对话一行一条：工具开始、输出、结束散成互不相干的行，没用协议给的 `call_id`。

codex、crush、pi、gemini-cli、opencode 的做法：光标坐标由排版给出、画帧时先藏光标；同步输出；输入框按屏高设上限；弹窗是浮层。问题不在语言。

## 决策

1. **Bubble Tea v2 + Lip Gloss v2，不换语言。** `View` 声明 `AltScreen` 与 `Cursor`，光标坐标由 `editor.view` 一并给出。v2 渲染器按格子比较前后两帧，终端支持时用同步输出，不支持时画帧前后藏光标、显光标。
2. **帧在 client 里解一次**（`client.Frame.UnmarshalJSON`）：推送（`event`）与回放（`type`）解成同一种结构，载荷是开放键集。
3. **对话按条目存，正文按逻辑行存**（`transcript.go`）。类别（`kind`）是数据：样式、首行前缀、可选的头一行。工具调用按 `id` / `call_id` 是一条，状态就地改，输出默认只显示末尾 5 行（Ctrl+O 展开）。每个逻辑行缓存自己的渲染结果，正文只往后长，所以流式输出时每帧只重画还开着的最后一行。
4. **画面按区域排**（`view.go`）：每帧恰好铺满；输入框最多 max(3, 屏高/3) 行，屏幕再矮也只让输入框的行数；审批框、子面板、斜杠菜单从历史区底部往上盖；每行按屏宽截一刀。
5. **原文画的时候才清洗**（`printable`）：一个转义序列可能被拆在两帧里。**折行按 UAX #14**：中文字间可断，标点不落行首。

## 不做

鼠标模式（保持 ADR-0020 §2）；启动时探测宽度不确定的字符；大段粘贴折叠成占位符。

## 后果

- 依赖换成 `charm.land/bubbletea/v2`、`charm.land/lipgloss/v2`，加 `github.com/rivo/uniseg`。
- 推送流由 `pump` 喂给程序，断线隔一秒重连（与 realagent-mcp 同一个写法）。
- 用 pyte 验证时要补上 SU/SD（`CSI S` / `CSI T`）：v2 在 xterm 类终端上用它们滚屏，pyte 不认，看到的残影是假的。
