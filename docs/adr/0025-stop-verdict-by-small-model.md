# ADR-0025：收工归小模型判 —— 出口从一个工具变成一次判定

- 状态：已采纳（2026-09-09）
- 依赖：ADR-0009（模型数据表与计价）、ADR-0010（不做档位间回落）、ADR-0017（三套协议、端点无默认）、ADR-0019（多 agent 有向图、一层循环一圈一个 turn）、ADR-0024（hook 的 `Stop` 位置）
- 取代：ADR-0019 §5 里「出口只有一个：模型调 `stop` 工具」那一条

## 背景

2026-08-29 定下的出口是一个工具：主模型自己调 `stop`，loop 认结果里那个 `stop: true` 字段收工。
「这次没调工具」不算收工，因为那只是它一句话说完了，不代表活干完了。

判断本身是对的，落点错了。**那是让干活的那个模型兼任裁判**，而它对「结束」的意识本来就不清晰。
于是代码里长出三处补丁，全都在治同一个病根：

1. system prompt 里写一段 `stop` 契约；
2. 契约不够，再配一个「输出回答的同时调用 stop」的范例；
3. 范例还不够，它回了话又没打 stop 时，core 补一条 user 消息提醒它，跑一圈再问一次。

第 3 条最贵：**每一次「它说完了但没打 stop」都要多打一整轮主模型调用**，
上下文越长这一轮越贵，而这一轮问的是一个是非题。

还有一笔更难看的账：`stop` 占着模型的工具清单里一格。ADR-0018 立过一条规矩——
工具每多一个，模型每次调用就多一次选错的机会。这一格换来的不是一个能力，是一个仪式。

## 决策

### 1. 出口是一次判定，不是一个工具

**主模型这一轮一个工具都没调时，把这一趟的抄本交给小模型（`small_model`），它说了算：**

- 说干完了 → 收工，回 idle；
- 说没干完 → 把它给的理由递回主模型，接着跑下一圈。

主模型的工具清单里因此**没有 `stop`**（`src/tools/stop.cpp` 一并删除，内置工具从六个回到五个）。
它也不需要知道有裁判这回事——system prompt 里换成一句循环契约：没有下一步动作时，写完回答、
一个工具都别调。**「没调工具」重新变回它字面的意思**，不再是一个要模型记住的信号。

三处补丁一起消失：契约、范例、提醒。为多问一次是非题而多打的那一整轮主模型调用也消失了，
换成一次小模型调用——那正是 ADR-0010 给小模型划的活。

### 2. 判定与 recap 是同一次调用

裁判要判「用户要的做到了没有」，就得先把这一趟干过的事数一遍。数出来的那份东西本身有用：
**recap**，一份写给没看过过程的人的回顾。所以一次调用交两样，JSON 里 `recap` 排在 `done` 前面——
不是排版，是让它先数完再判。

recap 有两个现成的消费者，两个今天都吃着次品：

- **完成通知**（`Agents::on_done`，沿入边发给邻居 agent）：从前带的是最后一条 assistant 正文，
  而那常常只是一句「好了」。邻居要的是「这一趟干了什么」。
- **`agent_end` 帧**：多一个 `recap` 字段（帧形状恒定，没有裁判时是空串）。

**不做上下文压缩。** recap 不回写进历史，历史一个字都不动。CONTEXT.md 那句「第一版不做上下文压缩」
仍然成立，hook 的 `PreCompact` 仍然不适用。

### 3. 抄本怎么裁：user 消息一条不丢

交给裁判的不是整段历史，是**这一趟的抄本**（`run_transcript`，一趟的起点就是 `start_run` 那一刻的
历史长度）。裁法照抄 Claude Code 压缩上下文那套的取舍：

- **user 消息一条不丢**——那是意图，丢了就无从判断「用户要的做到了没有」；
- 助手正文、工具调用、工具结果按行截断（600 字符），超了整份预算（24 KB）从旧到新丢，
  丢过就说一句 `…(earlier steps omitted)`；
- **thinking 不进抄本**：那是模型对自己说的话，判「做到了没有」用不上，而它常常是最长的一块。

丢掉的是过程，留下的是意图与现场。

### 4. 裁判自己说过的话要认得出来

打回给主模型的那条消息也是一条 user 消息（凡是从 agent 外面来的输入都是 user，ADR-0019 §5），
下一次判定就会在抄本里再看见它。**开头挂一个 `[supervisor] ` 标记**，抄本据此把它标成 supervisor
而不是 user。不标的话裁判会把自己上一次说的话读成用户的新要求，然后照着它去催第二遍。

### 5. 判不出来就收工

四条路一律判收工，因为它们的共同点是「裁判没能说不」，而**判不出来不该把人扣在循环里花钱**：

| 情况 | 为什么判收工 |
| --- | --- |
| `small_model` 没配 | 没有裁判。行为退回这个功能之前：没调工具就算干完了。**不回落到主模型**（ADR-0010） |
| 判定调用失败（端点报错、被中断） | 用户此刻已经看见主模型的回答了，这一趟对他而言是好的；把他扣在循环里才是坏的 |
| 回的不是 JSON | 它那段话原样当 recap。不重试——为一个杂活模型加一层重试，只是把一次判不出来变成三次 |
| JSON 里没有 `done` | 没说就是收工，不是「没说所以接着干」 |

`done` 写成字符串 `"false"` 认，那是小模型的常态，不是错误。

### 6. 连着三轮一个工具都没跑就强制收工

ADR-0019 立过「不设轮数上限」，理由是一个数字定不出「多少轮算跑飞了」。那条不变——
**这里数的不是轮数，是连着几轮一个工具都没跑**。裁判打回、主模型又什么都没干，这样连着三次，
就说明这一趟推不动了，再问下去只是两个模型互相说话花钱。跑过一次工具就清零：那是真的有进展。

这不是又一个可调参数，它不进配置。

### 7. 判定那次调用不往客户端推正文

裁判的产出是给它自己看的，推给客户端就是凭空多出来的一段助手发言。所以判定那次调用
`silent`：`message_update` / `thinking_*` 一律不广播。

**钱照报**：`usage` 与 `status_update` 不受 `silent` 影响，那次调用的花费算进这一趟的 `run_cost_`。
花掉了就是花掉了。

## 后果

- 出口仍然只有一个，且仍然是「一次判断」——只是判的人换了，从干活的那个换成一个不干活的。
  出错与用户中断照旧收工，那两条从来不归任何模型决定。
- 每次「主模型说完了」多一次小模型调用。换掉的是每次「它忘了打 stop」多一整轮主模型调用，
  以及工具清单里那一格。
- `Stop` hook 的位置从「模型调了 `stop`」变成「判定说这趟到头了」。它仍然只观察，不改控制流。
- 客户端不必改：`agent_end` 仍是唯一的收工信号，只是多带一个字段。TUI 一个字未动。
- **判定期间用户照样能中断**：那也是一次 curl，`abort_` 一样停得住它。
