# ADR-0021：agent 按客户端分组，组随客户端生灭

- 状态：已采纳（2026-08-28）
- 补充：ADR-0019（多 agent；本 ADR 给那张图划上所有权边界）
- 依赖：ADR-0006（core 常驻服务、QUIC）

## 背景

[[ADR-0019]] 定下「一台机器一个 core，core 里同时活着多个 agent」。它漏了一件事：**core 里的 agent 全糊在一起。**

真实用法是用户开三个终端窗口做三件事。三个 TUI 连同一个 core 进程，如果 agent 不分家，A 窗口的 `GET /agents` 会列出 B 窗口的 agent，Esc 一按可能中断的是隔壁那个。

同时 ADR-0019 还留着一个没有归宿的问题：**agent 什么时候被回收。** 那份 ADR 只说了「不做级联 close」，代价一栏承认会出现「没人等它产出、却还在烧钱跑的孤儿 agent」。

两件事其实是一件：**agent 需要一个所有者，而所有者就是那个客户端。**

## 决策

### 1. 组的单位是客户端

一个客户端 = 一个组。组**没有名字**——一个客户端只看得见自己那一组，不需要指认别的组。

- `client_id` 由客户端进程启动时生成，**不落盘**。三个终端窗口 = 三个 id = 三组。
- `POST /agent` 带 `client_id`；该客户端还没有组就顺手建组。
- **`spawn` 出来的 agent 属于创建者所在的组**。这不是「继承」这种需要判断的东西——组就是所有权边界，一个 agent 不可能属于别的组。

### 2. 隔离是硬的

- `GET /agents` **只列调用方那一组**
- `POST /message` / `POST /interrupt` / `GET /history` 只能作用于本组的 agent；**跨组的 id 一律当「无此 agent」**，不区分「不存在」与「不是你的」——区分了就等于告诉调用方别的组里有什么
- **边不跨组**。这条自动成立：`spawn` 的 `peers` 必须是创建者认识的，而它只认识同组的

于是可见性是**两层**：客户端看得见本组全部，组内 agent 只看得见自己的出边邻居（ADR-0019 的能力模型在组内照常成立）。

### 3. 组的生命周期：显式创建，测活维持，60 秒无连接即关

- **创建**：客户端主动建（第一次 `POST /agent`）
- **正常退出**：TUI 退出前显式发一次关闭（`POST /group/close`，体 `{client_id}`）
- **异常**：core 测活，**连接断开满 60 秒即关组**

**测活不自己造。** QUIC 有原生的 `max_idle_timeout` 与 PING 帧，quiche 直接暴露——把它设小（10 秒量级），连接死了 core 立刻知道。应用层只需要一件事：**连接断开那一刻起记一个 60 秒的表，期间同 `client_id` 重连就撤销，超时就关组。**

那个表挂在 `on_tick` 上（事件循环每轮已经在做 statusline 比对与事件 flush），**零新线程**。

- 实况注（2026-10-08）：[[ADR-0026]] 换成 HTTP/1.1 + WebSocket 之后没有事件循环了，`on_tick` 随之消失。断线时刻记在 `Server` 里（同一个 `client_id` 的最后一条 `/events` 连接断开那一刻），`main` 里一条 reaper 线程每 5 秒取一次「断线满 60 秒」的 client 关组。测活靠的是 WebSocket 读失败，不是 QUIC PING。

- 实况注（2026-10-08）：组隔离此前只在协议文档里成立，core 一直没读 `client_id`。现已落地：`Agents` 按组存节点；推送帧与 `permission_request` 只发给那一组的连接（每个 agent 拿一份事件出口绑定到本组的 `CoreContext`）；「有没有客户端能裁决」也按组判。

**关组的顺序写死**：先 `interrupt` 组内每个在跑的 agent，等它们停在检查点，再逐个 close。直接 close 一个正在跑的 agent，它的线程会往一个已经拆掉的收件箱里写。

### 4. 「agent 没有客户端也跑」的范围被缩小了，这是有意的

ADR-0019 写着「agent **没有任何客户端连着也照跑**」。本 ADR 之后这句话只在一个读法下成立：

> **subagent 没人盯着也跑**——客户端连着，只是在看同组的别的 agent。

**「TUI 全退了 agent 继续跑」的读法没有了。** 因此「派一个 agent 跑两小时的重构，关掉终端去睡觉」这个用法**明确不做**。

考虑过一个 `detached` 开关（声明某组不测活），**否决**：它把刚消灭掉的孤儿组换个名字请回来，而且用户得自己记着去关。换来的是一个干净得多的生命周期——**core 里不存在没有所有者的 agent**，ADR-0019 代价一栏那条孤儿 agent 的风险随之消失。

代价是「关终端去睡觉」真的没有了。记在这里，将来真有人要，加的就是那个 `detached` 开关。

### 5. 留不留记录由「谁创建的」决定，不是一个参数

- **TUI 创建的 agent** → 会话落 `<workdir>/.realagent/sessions/`
- **`spawn` 出来的 agent** → 会话落 `<workdir>/.realagent/sessions/sub/`

**清单只扫顶层**，所以 `sub/` 里的不进会话列表。ADR-0019 第 6 节那条规则一字不改地继续成立：**会话文件不在被扫的目录里 ⟹ 不在列表里**，不需要「展示」字段、不需要过滤器。

`spawn` 因此**没有 `persist` 参数**——这个决定不该由模型做，它取决于「谁创建的」，而那是 core 已经知道的事实。

**为什么两边都落盘，而不是 subagent 干脆不落**：ADR-0019 第 7 节的内存判据是「内存里那份是不是副本」。不落盘的 agent，内存那份是唯一的一份、丢不得，于是常驻——一个组里十几个 subagent 的历史会全程占着内存，而它们恰恰是 idle 最久的那批。

**但更重的代价是查不了问题**：subagent 改错文件、死循环、把钱烧光，用户想看它到底干了什么，盘上什么都没有；组一关那段历史彻底消失。这跟 CONTEXT.md [[Session]] 那句「它是记录，不是缓存」是反的。

**「不留记录」要的是「别污染我的会话列表」，不是「我不想要这些数据」。** 换个目录同时满足两者，且不新增任何开关。

代价：盘上会攒 subagent 的会话文件。**不做清理策略**——JSONL 是纯文本，一次 subagent 几十 KB，跟 `.git` 比可以忽略；真嫌多就 `rm -rf sub/`。

## 代价与保留

**`client_id` 不落盘，所以 TUI 被 `kill -9` 之后那一组必然在 60 秒后被关掉**，即使用户马上重开 TUI 也拿不回来（新进程 = 新 id）。这是刻意的：能拿回来就需要「列出孤儿组 + 认领」，而列出别人的组、接管别人的 agent 正是隔离的反面，要做就得先有一套身份认证。

**跨组协作不可能。** 三个窗口的 agent 之间没有任何通路。真要协作就在同一组里 `spawn`。

**没有「组的名字」也就没有切组。** 一个客户端终身对应一个组。

**60 秒是个选定的数，不是推导出来的。** 它要同时容得下「网线抖一下」和「用户 `Ctrl-Z` 挂起 TUI 又想起来」，同时短到不至于让忘关的窗口一直占着内存。真觉得不合适就改这一个常量，没有别的东西依赖它。
